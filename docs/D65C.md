# D65 H, slice C — implementation and measurements

Started 2026-10-11 from `c0e1b5c`, branch `wt/d65c`.

The source confirms M2's diagnosis: fingerprint records only survive or purge;
merges cannot recover their text. H0 is retained as codec 2 for comparison.
Codec 1 remains the default while the experiment runs.

Plan:

1. Refresh an isolated `$HOME` catalog and freeze a common readable population.
   Record document/unreadable counts and check codec 1's warm rare-term p90.
2. Add separate codecs for C1 (fingerprint runs with delta DocIds), C2 (C1
   with verified graduation), C3 (C1 with first offsets and verified graduation).
   Verification must establish the indexed version; missing or changed files
   keep their records. Offsets are hints and mismatches fall back.
3. Drive real lookup/follow/merge regression tests, including forced collisions,
   version changes, Unicode normalisation, wrong offsets and repeated merges.
   Run the existing H oracle and restart cases against every arm.
4. Run one benchmark at a time: five real lifecycle builds, 100-round S2 churn,
   size-stratified cold/warm queries, graduation and merge CPU/read counters.
5. Record results and a D65 decision brief; run fmt, clippy and workspace tests.

No measurements yet. Results will be appended as runs finish. Benchmark
artifacts stay outside git; summaries and reproducible commands go here.

## Progress and verified differences

The isolated refresh used the existing product crawl with ignore rules:

```sh
XDG_CONFIG_HOME=/tmp/d65c/config XDG_STATE_HOME=/tmp/d65c/state \
XDG_CACHE_HOME=/tmp/d65c/cache XDG_RUNTIME_DIR=/tmp/d65c/runtime \
FERRET_NO_DAEMON=1 target/release/ferret --index /tmp/d65c/catalog index /home/dave
```

It published **112,365 documents**, 395,884 names and 394,203 inodes, in
19.00 s (2026-10-11). Frozen readable/unreadable counts are pending.

Current main writes paired term/trigram segments, and merge selection uses
combined file bytes. M2 predates that implementation. The trace and lifecycle
runs will use today's real follow/merge policy, report term bytes separately,
and distinguish term-only from paired write amplification.

Another soundness constraint: one fingerprint record can represent two
colliding terms in the same document. Removing that record after graduating
only one term loses the other term. C2 checks all matching tokens before
removal. C3 marks deduplicated collisions with an unknown offset and preserves
records when the offset's enclosing run also has a colliding token. A failed
version check never licenses graduation. Dictionary and record lookups remain
unioned in all arms.

Codecs are 1 (control), 2 (`h`/H0), 3 (`c1`), 4 (`c2`), 5 (`c3`). The new codecs
have separate format identifiers; codec 1 stays the product default. Existing
merge callers without a checked reader carry records without graduation.
All eleven existing H tests now run each of codecs 2–5, including the random
oracle, restart boundaries, cancellation, spilling and coverage rebuilds.
Five further tests drive verified merges: dictionary/record collisions,
changed and missing disk files, wrong-offset fallback with Kelvin-sign
normalisation, whole/part collisions at one offset, and partial merge sequences.
Affected crate tests are green (27 bench, 175 crawl, 76 index, 108 query).
Full workspace gates are pending.

The full workspace tests pass **935 tests**, versus main's 928 (seven added
regressions), and clippy is clean. One overlapping rebuild briefly left the
previous gate attempt unable to execute a test binary; the subsequent workspace
run completed with the full count. No dependencies changed. A later final gate
will use a separate log. Window boundaries now require a decoded separator;
a truncated UTF-8 alphanumeric cannot invent a certain token.

## Corpus and first measurements

A second refresh after implementation published **112,382 live documents**.
The checked capture found **112,376 readable**, **6 changed/unreadable**, and
**3,978,812,718 text bytes**. All arms use those identical frozen bytes through
real follow; queries retain the full catalog live set (no `--covered` masking).
The old 5,656-document stale population is not used.

The codec-1 first build took 139.25 wall / 106.58 CPU seconds, with
312,580 KiB peak RSS: 120 segments, **531,778,265 term bytes**, 424,043,912
trigram bytes, 30,301,123 dictionary singletons. Steady/full and latency are
still running. Today's paired flush/merge boundaries differ from M2's 45-segment
first build; this experiment compares all five arms under current main's policy.

`crates/ferret-bench/scripts/d65c.py` serializes `index-build`, all three
lifecycle `content-query` runs and 100-round `index-churn`. Every subprocess
preflights the three benchmark binary names with `pgrep -x`. `--cleanup-states`
removes only first/steady measurement copies after their query logs are saved;
it shares byte-identical full-merge trigram files after measurement to keep the
five valid full indexes without exhausting the scratch disk.

Latency uses a stratified df1 sample (up to 50 per file-size bucket), and up to
50 per bucket from an 800-term reservoir for df2–100. The bucket for a query
is the largest reference matching document; a second partition reports the
largest document actually sent for verification. The latter includes collision
hits and unreadable fallback attempts. Absent queries with no readable hits
have no verified-file size. Medians across the stratified mix are not weighted
by the corpus's natural size distribution. Cold evicts the index and every
candidate document observed by an untimed pass; warm repeats the compiled query.

Codec 1 finished: **450,277,507 B steady** (12 segments) and
**398,117,410 B full**. Steady/full merge CPU: 156.68 / 58.54 s. Its warm
p90 is **0.15 ms df1, 0.15 ms df2–100, 0.12 ms absent** at steady state,
and 0.03 / 0.04 / 0.03 ms fully merged. This confirms the stale-catalog floor
is gone. At the 120-segment first build, rare warm p90 is 1.37–1.39 ms;
that is segment fan-out, not the old catalog floor.

C2 batches candidate records by document and reads each candidate document
once per merge. It tokenizes those stable bytes, confirms each recovered
spelling in an actual input dictionary, and sorts the confirmed occurrences
for the term stream. Removing a shared collision record still requires a
unique matching token spelling and a resulting dictionary df above one.
C3 uses its window hints in the streaming term merge, with full fallback.
The additional C2 regression checks the one-read-per-document property through
the real spilling merge. Merge `rchar` and device-read counters are also
reported; input-file sizes alone are not actual I/O.

Control queries returned no readable verification bytes: their six verification
attempts were the unreadable population. The initial control log's attempted
size partition labels those as ≥1 MiB; that partition is not a readable-file
latency. The reference size partitions and latency timings are valid. The
harness now distinguishes attempted from successfully read documents and
reports both verification attempts and readable documents per query.

The batched C2 implementation and readable-file accounting pass all gates:
**936 workspace tests**, clean formatter and clippy. No dependency changes.
