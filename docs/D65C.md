## Corpus and method

The source confirms M2's diagnosis: H0 fingerprint records can only survive or
purge. Once demoted, their text cannot be recovered without reading a document.
The brief's M2 figures (53% smaller on `$HOME`, 10.4% larger under churn) are
accurate. Main now writes paired term/trigram segments and selects merges by
combined bytes; M2 predates this policy. These measurements report term bytes
and term write amplification separately from paired values.

The isolated catalog was refreshed with the existing crawl and ignore rules:

The final refresh published **112,382 live documents**, 395,878 names and

and captured **112,376 readable document representatives**, **6 changed/unreadable**, and
**3,978,812,718 bytes**. All five real follows consume these identical frozen

```sh

# Repeat serially for h0, c1, c2, c3.
python3 crates/ferret-bench/scripts/d65c_results.py --run-dir /tmp/d65c --output-dir docs/measurements/d65c
```

The driver runs `index-build --codec … --snapshots`, then `content-query` at
first build, steady state and full merge, then `index-churn … 100 --codec …`.
Every subprocess preflights `ferret-bench`, `term-dict-bench` and `pair-fp-bench`
with `pgrep -x`. All runs are foreground and serialized. Indexes are built by
real follow and merge, never converted from the control. Measurement copies
are cleaned only after queries; byte-identical full trigram files are shared
after measurement to fit the scratch disk. Raw logs remain in `/tmp/d65c`.

Latency has two samples: independent uniform 50-term df1/df2–100 reservoirs
for the aggregate D65 gate, and up to 50 queries per size stratum. The df2
sample uses an 800-term reservoir plus rare terms found in 5,000 seeded small
documents (confirmed against actual control df and every matching file size).
Stratified totals are not weighted by the corpus's natural distribution.
Buckets are <4 KiB, 4–64 KiB, 64 KiB–1 MiB, ≥1 MiB, and no readable verification.
The reference partition uses the largest matching document; the verification
partition uses the largest successfully read document, including collision hits.
Attempts and readable documents are counted separately. Cold evicts the index
and the candidate documents found by an untimed pass; warm repeats the compiled
query. Every experimental query compares its actual row identities with the
fully merged codec-1 control. Mid and common classes use 50 queries each.

Churn is S2's seeded 100-round trace: 2,000 births per round, 1/20 death
probability, 200,000-word vocabulary, 20–400 words plus a unique term per
document. Ordinary-trace WA is `(follow bytes + merge outputs) / follow bytes`.
Its forced final full merge is measured separately, including final purge.
Merge CPU, `/proc/self/io` logical `rchar`, device reads, and actual returned
document bytes are reported. Input segment sizes are reported separately.
Synthetic window bytes are logical bytes; generating their source is CPU work.

## Implemented arms and soundness

| Arm | Format | Implementation |
| --- | --- | --- |
| Control | codec 1 | Existing dictionary/postings, unchanged default. |
| H0 | codec 2, `h`/`h0` | Existing fixed fingerprint records preserved. |
| C1 | codec 3, `c1` | Fingerprint stored once per run, delta DocIds, fixed 128-record restart blocks. |
| C2 | codec 4, `c2` | C1 plus verified graduation, candidate records grouped by document and read once per merge. |
| C3 | codec 5, `c3` | C1 plus vbyte first offsets, checked window graduation and query verification, full-read fallback. |

C2 uses input dictionary fingerprints only as a candidate filter. It tokenizes
stable document bytes, checks each recovered normalised spelling in an actual
input dictionary, then feeds confirmed occurrences into the term stream. A
record is removed only if its fingerprint denotes one token spelling in that
document and the resulting dictionary df exceeds one. C3 stores unknown hints
for deduplicated collisions and checks whole/part collisions at the same offset.
A shared record cannot disappear after graduating only one colliding term.
Changed/unreadable documents never graduate. A positive window check requires
the entire enclosing tokenizer run and decoded boundary separators; truncated
UTF-8 cannot invent a certain token. Hosts bracket the indexed stat before and
after reads. Callers without a checked reader keep records without graduation.

All eleven original H tests run codecs 2–5: random oracle, restart boundaries,
union lookup, spill, cancellation, purge and rebuild. Nine added collected
regressions drive the real merge/query paths: forced dictionary/record collision,
changed and unreadable disk files, wrong-offset fallback with Kelvin-sign
normalisation, same-offset whole/part collision, repeated partial merges against
the tokenizer oracle, truncated UTF-8 boundaries, C2 one-read-per-document,
C3 actual query fallback, and known offset hints across restart/purge boundaries.

The final harness passes **937 workspace tests** (main: 928), formatter and
clippy with zero Rust warnings. No Cargo manifest or lockfile changes.

### Graduation implementation correction (2026-10-12 local)

The C2 figures above are a prototype; C3’s first merge was stopped before
steady results because it repeatedly probed record blocks and could repeat
whole-file fallback checks. Both graduation arms now collect actual input
dictionary spellings once and batch candidate records by document. C3 still
verifies offsets, but reuses stable full bytes after its first full fallback
(or complete window), checking all colliding spellings before record removal.
An additional real-merge test checks three bad offsets use one full read.
C2/C3 are being rerun from fresh follows. Control/H0/C1 home results remain
valid. The original C2 and partial C3 are archived as pilots, not final arm
verdicts. Churn also gains untimed raw/live records-per-lookup samples.

The corrected batched graduation implementation passes all required gates:
**938workspace tests** (10more thanmain), formatter/clippy clean. This includes
the one-full-fallback realmerge regression and all originalcollision,changed
file,Unicode,oracle and restart cases. Release rebuild and freshC2/C3 follow.
