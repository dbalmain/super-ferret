# D65 H, slice C — implementation and measurements

2026-10-11–12 (Australia/Sydney), branch `wt/d65c` from `c0e1b5c`. Codec 1 remains the default.
Measured on AMD Ryzen 9 9955HX (16 cores / 32 threads). No dependencies changed.

## Corpus and method

The source confirms M2's diagnosis: H0 fingerprint records can only survive or
purge. Once demoted, their text cannot be recovered without reading a document.
The brief's M2 figures (53% smaller on `$HOME`, 10.4% larger under churn) are
accurate. Main now writes paired term/trigram segments and selects merges by
combined bytes; M2 predates this policy. These measurements report term bytes
and term write amplification separately from paired values.

The isolated catalog was refreshed with the existing crawl and ignore rules:

```sh
XDG_CONFIG_HOME=/tmp/d65c/config XDG_STATE_HOME=/tmp/d65c/state \
XDG_CACHE_HOME=/tmp/d65c/cache XDG_RUNTIME_DIR=/tmp/d65c/runtime \
FERRET_NO_DAEMON=1 target/release/ferret --index /tmp/d65c/catalog index /home/dave
```

The final refresh published **112,382 live documents**, 395,878 names and
394,197 inodes. `ferret-bench index-freeze` checked the indexed file version
and captured **112,376 readable document representatives**, **6 changed/unreadable**, and
**3,978,812,718 bytes**. All five real follows consume these identical frozen
bytes. Queries retain the full live catalog, including the six misses; no
`--covered` masking. The old 5,656-document stale population is not used.

```sh
python3 crates/ferret-bench/scripts/d65c.py control all --run-dir /tmp/d65c --cleanup-states
# Repeat serially for h0, c1, c2, c3.
python3 crates/ferret-bench/scripts/d65c_results.py --run-dir /tmp/d65c --output-dir docs/measurements/d65c
```

The driver runs `index-build --codec … --snapshots`, then `content-query` at
first build, steady state and full merge, then `index-churn … 100 --codec …`.
Every subprocess preflights `ferret-bench`, `term-dict-bench` and `pair-fp-bench`
with `pgrep -x`. All runs are foreground and serialized. Indexes are built by
real follow and merge, never converted from the control. Measurement copies
are cleaned only after queries; byte-identical full trigram files are shared
after measurement to fit the scratch disk. Raw logs remain in `/tmp/d65c`.

Latency has two samples: independent uniform 50-term df1/df2–100 reservoirs
for the aggregate D65 gate, and up to 50 queries per size stratum. The df2
sample uses an 800-term reservoir plus rare terms found in 5,000 seeded small
documents (confirmed against actual control df and every matching file size).
Stratified totals are not weighted by the corpus's natural distribution.
Buckets are <4 KiB, 4–64 KiB, 64 KiB–1 MiB, ≥1 MiB, and no readable verification.
The reference partition uses the largest matching document; the verification
partition uses the largest successfully read document, including collision hits.
Attempts and readable documents are counted separately. Cold evicts the index
and the candidate documents found by an untimed pass; warm repeats the compiled
query. Every experimental query compares its actual row identities with the
fully merged codec-1 control. Mid and common classes use 50 queries each.

Churn is S2's seeded 100-round trace: 2,000 births per round, 1/20 death
probability, 200,000-word vocabulary, 20–400 words plus a unique term per
document. Ordinary-trace WA is `(follow bytes + merge outputs) / follow bytes`.
Its forced final full merge is measured separately, including final purge.
Merge CPU, `/proc/self/io` logical `rchar`, device reads, and actual returned
document bytes are reported. Input segment sizes are reported separately.
Synthetic window bytes are logical bytes; generating their source is CPU work.

## Implemented arms and soundness

| Arm | Format | Implementation |
| --- | --- | --- |
| Control | codec 1 | Existing dictionary/postings, unchanged default. |
| H0 | codec 2, `h`/`h0` | Existing fixed fingerprint records preserved. |
| C1 | codec 3, `c1` | Fingerprint stored once per run, delta DocIds, fixed 128-record restart blocks. |
| C2 | codec 4, `c2` | C1 plus verified graduation, candidate records grouped by document and read once per merge. |
| C3 | codec 5, `c3` | C1 plus vbyte first offsets, checked window graduation and query verification, full-read fallback. |

C2 uses input dictionary fingerprints only as a candidate filter. It tokenizes
stable document bytes, checks each recovered normalised spelling against the actual
input dictionary spellings collected once per merge, then feeds confirmed occurrences into the term stream. A
record is removed only if its fingerprint denotes one token spelling in that
document and the resulting dictionary df exceeds one. C3 stores unknown hints
for deduplicated collisions and checks whole/part collisions at the same offset.
A shared record cannot disappear after graduating only one colliding term.
Changed/unreadable documents never graduate. A positive window check requires
the entire enclosing tokenizer run and decoded boundary separators; truncated
UTF-8 cannot invent a certain token. Hosts bracket the indexed stat before and
after reads. Callers without a checked reader keep records without graduation.

All eleven original H tests run codecs 2–5: random oracle, restart boundaries,
union lookup, spill, cancellation, purge and rebuild. Ten added collected
regressions drive the real merge/query paths: forced dictionary/record collision,
changed and unreadable disk files, wrong-offset fallback with Kelvin-sign
normalisation, same-offset whole/part collision, repeated partial merges against
the tokenizer oracle, truncated UTF-8 boundaries, C2 one-read-per-document,
C3 actual query fallback, known offset hints across restart/purge boundaries,
and C3 reusing one full fallback for several bad hints in one document.

The final harness passes **938 workspace tests** (main: 928), formatter and
clippy with zero Rust warnings. No Cargo manifest or lockfile changes.

The fresh control's steady warm natural df1 p90 is **0.12 ms** (stratified
0.14 ms), confirming the old floor is gone. All **7,500 experimental queries**
(625 × three states × four arms) matched the control, with zero mismatches.
The six uncaptured representatives are not an exhaustive check of every alias.

C3 reuses a complete/full fallback across all candidate records in a document;
a positive partial window only graduates the token it actually proves. The
current graduation spelling, candidate and occurrence buffers grow with merge
input rather than spilling within a fixed memory bound. Peak memory is reported
below; this limits production adoption independently of soundness.

H0 and C1 pass the size and CPU gates but fail df2–100 p90 and the mid median.

gate. Codec 1 therefore remains the default; codecs 2–5 are opt-in experiments.

The diagnosis holds: the one-way population keeps all 30.30M HOME records
until graduation is enabled. C1 removes most of the compact churn penalty
without reducing query verification. C2 graduates 8.83M records through full
merge, while C3 reaches the same final population using offset checks.

The brief's historical M2 numbers are correct, but today's paired term/trigram
merge selection changes the ordinary churn state: H0 is **10.3% smaller** there
and **10.8% larger** after full merge. Compare matching states, not the old
term-only trace with today's fragmented paired trace. C3 also reaches three
HOME steady segments, versus twelve for the other arms; its latency is the
measured lifecycle outcome, including that different merge graph.

C1 adds no offset field, but its run lengths/restart encoding add **30.42 MB**
to H0 at first build. C3 adds **94.39 MB** over C1 there (3.12 B/record including
section overhead), rather than the derived 80 MB: this fresh corpus has more
records. C3's successful query windows are usually 1,280 B, but its steady
graduation still reads **9.33 GB**, against C2's **9.57 GB**, through **38×** as
many document reads. At least 6.49 GB must be full checks because each window
is capped at 1,280 B. Offsets improve typical queries much more than merge I/O.
C3's natural df2–100 warm p95 is still **32.91 ms**; passing p90 does not bound
that tail.

Cold observations vary substantially between serial runs and size strata;
these are single runs, so they establish observed costs rather than isolating
every cache/device effect. Synthetic C3 readers regenerate the source before
returning a window: their CPU includes generation, and returned window bytes
are logical bytes, not physical disk reads. HOME reads use real files.

A next experiment could coalesce nearby windows or choose one full read for
dense candidate documents, with a verification budget and bounded buffers.
Skipped verification must leave records intact. This proposal is unmeasured;
it does not establish that C3 can meet the CPU gate.

## Offsets without graduation (C4)

2026-10-12, same catalog, frozen corpus, driver and methods as above. Two new
arms share codec 5's on-disk record format and differ only at merge:

| Arm | Format | Merge |
| --- | --- | --- |
| C4a | codec 6, `c4a` | No graduation. A demoted dictionary term's record gets its first offset from a checked full read, as C3 does. |
| C4b | codec 7, `c4b` | No graduation and no merge-time reads. A demoted record carries the unknown-offset hint; a query checks the whole document for it. |

A query treats a record as Maybe in both arms, and confirms it in the offset
window or falls back to a full check, exactly as C3 does. Merges now count
document reads by purpose (`*_graduation_reads`, `*_demotion_reads` and their
byte counts). The new collected test drives the real `stream_verified` for
codecs 5–7 over one graduation candidate and one demotion: C3 does one read
of each kind, C4a does only the demotion read, and C4b never calls its reader
and writes the unknown hint. All eleven original H tests and the collision and
changed-file tests now run codecs 2–7, and the query fallback test runs codecs
5–7. **939 workspace tests** pass with zero warnings.
