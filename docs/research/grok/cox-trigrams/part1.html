Matching can be simple and fast

A recursive matcher is easy and can take exponential time. Thompson’s NFA reads the text once, keeping a set of states. Same answers, linear in the text.

Read

Regular Expression Matching Can Be Simple And Fast (Cox, 2007), through “Implementation: Simulating the NFA.” The C is nfa.c. You will reimplement the algorithm, not the C.

Cox compiles infix to postfix with . as an explicit concat operator, then a stack of NFA fragments. You may parse to an AST and build the graph recursively instead — same fragments, no postfix. The tests never see postfix.

Lesson — feel backtracking die

On paper, match a?a?a?aaa against aaa by “try one, then zero” for each ?. How many complete choices exist? Only the all-zero choice matches, and a backtracker reaches it last, having tried the other seven. That is 2n attempts for n optional as — and note that the work is spent on a pattern that does match. Against aaaaaaa, which cannot match at all, it tries every one of the eight and fails.

Optional: write a recursive matcher anyway. Do not run the harness against it. The pathological case (a? twenty times, then twenty as, text twenty as) is in pathological.json and will kill this approach.

Lesson — Thompson fragments

Each subexpression becomes a fragment: a start state and a list of dangling outgoing arrows. Operators glue fragments:

  • literal c — one state, labeled arrow out
  • concat — patch e1’s outs onto e2’s start
  • | — new Split, both ways, outs = e1.outs + e2.outs
  • ? — Split to e or skip
  • * — Split to e or skip; e’s outs loop to the Split
  • + — like star but start at e, not the Split

States: Char(c), Split (ε to two targets), Match (accept). One state per character or operator except parens. Draw a(bb)+a before you code it. Cox’s figures in the article are the spec.

Pencil. How many states does (a|b)* need under this construction?

Lesson — simulate all states at once

Two lists: current set, next set. To step on character c: for every Char state in current whose label is c, add its target to next, following Splits (ε-closure) as you add. Never put a state on a list twice in the same step (generation number / visited flag).

At end of input, accept if Match is in the current set. This is a whole-string match: that is the match command.

Work per character is O(number of states). States ≈ length of the pattern. Text of length n ⇒ O(n · m). The pathological pattern has m ≈ 40, n = 20. Instant.

Implement match PATTERN TEXT as in the interface.

Lesson — cache lists as DFA states (optional, same tests)

Each NFA state-set is a DFA state. Cache set × character → next set. Next time you see the same set, skip the NFA step. Throw the whole cache away when it grows past some bound — awk uses a fixed limit of 32 states, which is why its curve in Cox’s graph kinks at n=28. Cox’s version is dfa1.c; the uncached DFA is dfa0.c.

Same match command, and the same fixtures: run the harness as stage dfa. Nothing outside your program can tell a cached run from an uncached one, so this stage is on your honour — see what each stage tests.

Tests

No tests until match exists. Then:

python3 harness/run_tests.py --bin ./yourprog nfa # later: python3 harness/run_tests.py --bin ./yourprog dfa

match.json is ordinary cases. pathological.json is the exponential trap; timeout 1s. If nfa fails the trap, you are still backtracking, even if you think you are not.

The syntax stage runs off the same match command and can be attempted as soon as your parser exists. It feeds you unbalanced parentheses and repetition operators with nothing to repeat, and every one must leave with exit 2. Nothing else in the suite notices a parser that quietly treats ( as a literal.

python3 harness/run_tests.py --bin ./yourprog syntax

Part 1 does not test ., classes, substring search, or captures.
