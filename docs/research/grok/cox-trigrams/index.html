Implementing regular expressions, then indexing them

All four of Russ Cox’s articles, as a course. You write a matcher, then a virtual machine with captures, then a production-shaped engine, then a trigram index that feeds the matcher back its own candidates. The tests never see your source — only an executable and its JSON, so the language is yours.

swtch.com/~rsc/regexp · 2007–2012 · tests in harness/

Part 1 — Simple and fast

Backtracking is exponential. Thompson NFA is linear. Optional lazy DFA on top. Tests: nfa, dfa, syntax.

Part 2 — The VM

Regexps as bytecode. save tracks captures. Pike VM = Thompson in lock-step plus per-thread saved pointers. Tests: vm, submatch.

Part 3 — In the wild

What RE2 actually adds: ., classes, unanchored search, a bounded DFA cache. Tests: search, plus the earlier match suite still has to pass.

Part 4 — Trigram index

Compile a regexp to a boolean of trigrams, intersect posting lists, recheck with your matcher. Tests: index.

How to take this

  • Pick Python, Ruby, JavaScript, Go, or Rust. One program that grows. Stdlib only.
  • Read Cox when the lesson says to. Pencil before code.
  • Performance of the index does not matter. Performance of the matcher does in one place: the pathological case in part 1 must finish in a second, which backtracking will not.
  • The test harness is language-agnostic: it shells out to your binary and reads JSON on stdout. Debug prints go to stderr.

Regexp syntax (all four parts)

A tiny egrep subset. Same language in every part so the tests stay stable.

FormMeaning
juxtapositionconcatenation
|alternation (lowest precedence)
* + ?greedy repetition (highest)
(e)grouping; also a capture for part 2
.any single character — not concatenation. Cox’s C compiler uses . as concat only in an internal postfix form you never write.
[abc] [a-z]character class (required from part 3; earlier parts’ tests do not use them)
\escapes the next character (optional; fixtures avoid needing it)

No backreferences, lookaround, {n,m}, non-greedy *?, or anchors. match is implicitly anchored at both ends. search is unanchored.

Precedence, from tightest to loosest: repetition, concatenation, alternation. Thus ab|c means (ab)|c. Reject malformed patterns — an unbalanced (, a * with nothing to its left — with exit 2 rather than silently interpreting them; the syntax stage checks this.

The interface

Your program is an executable. Commands take arguments, print one JSON object to stdout, and exit 0. The match value must be a JSON boolean, not 0, 1, or a string; groups must be null on a non-match. Copy harness/example_stub.py or harness/example_stub.av if you want the argv parsing done.

ExitMeansStdout
0answered the questionone JSON object
2the pattern is not a legal regexpnothing (message on stderr)
1bad usage, or you crashednothing

Exit 2 is not decoration: the syntax stage feeds you malformed patterns and fails you for accepting any of them. A parser that treats a stray ( as a literal passes every other stage in the suite.

match PATTERN TEXT — parts 1 and 2

True iff the regexp matches the entire text (Cox’s nfa.c).

{"match": true}

search PATTERN TEXT — part 3 onward

True iff some substring matches (grep / Code Search). Implement as compiling .*? PATTERN and running the same engine, or by starting a new thread at every input position — both are linear if the engine is Thompson/Pike.

{"match": true}

submatch PATTERN TEXT — part 2

Whole-string match plus captures. Group 0 is the whole match. Then each ( in left-to-right order. Unmatched optional group: null. Offsets are byte or character indices, but fixtures are ASCII so they coincide. Half-open [start, end). Greedy: split prefers its first arm (Perl / Pike, not POSIX).

{"match": true, "groups": [[0, 6], [0, 3], [3, 6]]} {"match": false, "groups": null}

index-search --corpus DIR PATTERN — part 4

Build an in-memory trigram index of every file in DIR. Recursion is optional — the fixture corpus is flat. Search PATTERN as a substring regexp. Print two arrays of basenames, in any order and without duplicates (the harness sorts).

  • candidates — what the trigram query selected, before recheck. Must be a superset of the true hits; dropping one is a failed test. Several fixtures also pin it exactly, so you cannot pass by reporting the survivors instead.
  • hits — files that actually matched after recheck. Must equal the fixture list.
{"candidates": ["a.txt", "c.txt", "d.txt"], "hits": ["a.txt", "c.txt"]}

Running tests

Harness needs Python 3. You do not write Python unless you want to.

python3 harness/run_tests.py --bin ./yourprog nfa python3 harness/run_tests.py --bin ./yourprog nfa dfa vm python3 harness/run_tests.py --bin ./yourprog submatch python3 harness/run_tests.py --bin ./yourprog syntax python3 harness/run_tests.py --bin ./yourprog search python3 harness/run_tests.py --bin ./yourprog index python3 harness/run_tests.py --bin ./yourprog all

Each case is one process. Default timeout 2s; the pathological NFA case is 1s. Debug on stderr. A failing case prints the pattern, the text, and what the harness got.

The stub always returns no-match, so you can see the protocol work:

python3 harness/run_tests.py --bin harness/example_stub.py nfa python3 harness/run_tests.py --bin harness/example_stub.av nfa # FAIL nfa 22 passed, 29 failed (the 22 are the true negatives)

--bin must be executable (shebang is enough for the stub). For a compiled language, point at the binary. For interpreted languages without a shebang, write a one-line wrapper that execs the interpreter.

What the harness cannot see

nfa, dfa and vm run the same command against the same fixtures. They differ only in what you have built by the time you run them, and nothing outside your process can tell a state-set cache or a bytecode VM from the plain simulation. Those two stages are self-certified: they catch you breaking something, not you skipping something.

The DFA cache cap in part 3 is likewise untested, and the part-4 index is tested for soundness — never dropping a hit — but never for speed. Nothing here stops you writing a slow, correct engine. That is deliberate; correctness is the part a fixture can hold you to.
