Regular expression matching in the wild

RE2 is not a new algorithm. It is Thompson/Pike plus the operators grep actually needs, UTF-8 as bytes, and a DFA cache that does not eat RAM. You will add three of those; you will not clone RE2.

Read

Regular Expression Matching in the Wild (Cox, 2010). Skim the UTF-8 compiler and the reverse-DFA submatch discussion. Notice the split-priority picture: greedy vs non-greedy is which arm of Split comes first. You already did greedy.

Lesson — what “production” means here

Article 3 is a tour, not a spec. The implementable slice for this course:

  1. . and [abc] / [a-z] as instructions, not giant alternations.
  2. Unanchored search in linear time.
  3. The DFA cache from part 1, with a size cap. Optional, and untested — but it is the one item on this list that article 3 is really about.

You will not implement Unicode tables, POSIX classes, reverse matching, or RE2’s actual compiler. Part 4 needs (1) and (2) so the recheck can be your engine on real substrings.

Lesson — . and classes

New ops (names are yours):

  • any — consume one character, whatever it is. (Fixtures have no newlines; you may treat newline as a character.)
  • class(set) — consume one character if it is in the set. Build the set from [abc] and ranges [a-z]. No negation [^] in the fixtures.

In the NFA picture these are labeled edges whose label is a set, not a char. In the VM, one instruction. Expanding [a-z] into 26-way Split works and is a fine first version; a class instruction is what Cox says production engines do.

Parser: . is any-char, never concat. Concat is juxtaposition, as in part 1.

Lesson — unanchored search

Trying the pattern at position 0, then 1, then 2, and running to end each time is quadratic. Cox’s fix: prefix the compiled program with the compiled form of .*? (non-greedy any-char star) so the VM itself walks the string once.

.*? here is an internal construction, not new source syntax: emit an any-char loop whose Split prefers the pattern-start arm over the loop arm.

Non-greedy star is greedy star with Split arms reversed: prefer leaving the loop. For this course you may also start a fresh thread at every input position in the lock-step machine (add the start state to the next list every character). That is the same idea: the engine, not a for-loop in your host language, tries every start.

Add that fresh thread at lowest priority, so an earlier start always outranks a later one. It makes no difference to the search command, which reports only a boolean — but the moment you want to report where the match was, leftmost-first depends on it, and the bug will not show up in any fixture here.

The search command is this unanchored matcher. match stays whole-string. Keep both.

Lesson — bounded DFA cache

Article 1 already built the cache. Article 3’s operational note: throw it away when it gets large so a giant class × unicode alphabet cannot OOM you. Cap at 32 or 256 states; correctness is unchanged. No extra tests — if nfa and search pass with the cap on, you are done.

Reverse-DFA submatch (RE2 finds match bounds with a forward DFA then a reverse DFA) is the part you are allowed to only read about. Pike VM already gives you captures.

Tests

python3 harness/run_tests.py --bin ./yourprog nfa search

search.json uses ., [cd], [a-z], and substring patterns like Google.*Search. Whole-string match must still pass — search is an addition, never a replacement, and part 4 needs both. There is no separate “part 3 only” stage name beyond search.

Two cases are worth predicting before you run them: a* against zzz is true, because the empty match at position 0 is a substring match, and [a-z]+ against Hello is also true, on ello. If either surprises you, your unanchored wrapper is anchored somewhere.
