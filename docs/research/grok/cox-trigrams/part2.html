The virtual machine approach

The NFA graph is a program. Threads run it. A new instruction, save, records capture offsets without going exponential — if you run the threads in lock step.

Read

Regular Expression Matching: the Virtual Machine Approach (Cox, 2009), through “Pike’s Implementation.” Skip the POSIX digression. Companion: rsc/re1.

Lesson — bytecode is the NFA

Instructions:

Compile, from Cox’s tables:

a char a e1 e2 codes(e1) then codes(e2) e1|e2 split L1, L2; L1: e1; jmp L3; L2: e2; L3: e? split L1, L2; L1: e; L2: e* L1: split L2, L3; L2: e; jmp L1; L3: e+ L1: e; split L1, L3; L3: (e) save 2k; e; save 2k+1 for the k-th '(' (1-based k) plus save 0 at the start and save 1 before match, for group 0

Pencil. Write the program for a+b+ and for (a+)(b+). Check against the article.

The obvious interpreter of this bytecode — recurse on both arms of every split — is, in Cox’s words, the essence of Henry Spencer’s original library and of the backtracking engines in Java, Perl, PCRE, Python, and the original ed, sed and grep. Write it only to watch part 1’s exponential blow-up reappear in new clothes. The vm stage expects the lock-step version.

Lesson — Thompson as a VM

All threads share one SP (they walk the text together). Thread state is just PC. At most one thread per PC (identical PC ⇒ identical future). Process every current thread on the current character, producing the next list. Jmp/split/save happen in ε-closure when you add a thread, not when you consume a character — same as following Split nodes in part 1.

If this passes nfa fixtures via the match command, you have a correct lock-step VM. Stage name: vm.

Lesson — save

Each thread carries an array of saved pointers. save i writes SP into slot i on that thread’s copy. Failed threads die with their copies. The winning thread’s array is the answer.

Slot 0,1 = group 0 start/end. Slot 2k, 2k+1 = k-th capture. Report groups as [start, end) pairs built from those slots. Unmatched optional: the slot was never written — report null for that group. Initialize slots to a sentinel so you can tell.

Pencil. (a+)(a+) on aaa. Greedy first + takes as much as it can while leaving the second + at least one a. Groups: whole [0,3), first [0,2), second [2,3).

Lesson — Pike VM

Thompson VM + saved arrays = Pike VM, first used by Rob Pike in the text editor sam around 1985. Still one thread per PC: two threads at the same PC execute identically however their saved pointers differ, because those pointers record the past and never steer the future. So a later arrival at a PC can be dropped outright — and if you enqueue in preference order, the one already there is the one you wanted.

To respect greedy preference: add ε-targets recursively when enqueueing, highest priority first. When a Match is seen, record it but continue higher-priority threads on this character so a longer greedy match can win; discard lower-priority ones.

For this course, getting the submatch.json fixtures right is the definition of “respects greedy.” If a case fails, you added threads in the wrong order or overwrote a higher-priority save.

Tests

python3 harness/run_tests.py --bin ./yourprog vm python3 harness/run_tests.py --bin ./yourprog submatch

vm reuses match.json and pathological.json, yes/no only — the same fixtures as nfa, so passing it proves your VM agrees with your part-1 machine, not that you wrote a VM at all. submatch is submatch.json. Captures are ASCII offsets, and the harness insists on the documented shape: groups is null on a non-match, and otherwise an array of [start, end] integer pairs with null for a group that never matched. No POSIX leftmost-longest: the fixtures encode Pike/Perl greedy throughout.
