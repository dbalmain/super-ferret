Landscape

What you can install today, what files they actually read, and what sits on disk when they claim to have an index. Linux in full; Windows and macOS as the bars; engines as competitor intel you will reimplement, not link.

Primary sources: Recoll 1.44.1 manual and features page, Xapian Glass comments, SQLite FTS5 docs, Baloo source/bugs, voidtools FAQ, Apple/Microsoft docs, VictoriaLogs source. Reverse-engineering is labeled.

Beagle, Strigi, Glimpse, Namazu, Hyper Estraier, Swish-e and mg taught the inverted-index + extractor-plugin shape. Recoll is the only Linux app that still fully inhabits it.

Score against your brief

Lightning-fast names: FSearch / plocate / Everything, not Recoll. Body + boolean + phrase + nested docs: Recoll, not FSearch. Regex over contents: rga, not Recoll (wildcards and filename regex only). Small index: plocate and VictoriaLogs-class designs, not Recoll on HTML (73% of a Wikipedia dump). Near-real-time with a polite queue: nobody does this well; Pinot nices itself and pauses on battery; Recoll’s inotify daemon is known to be heavy on large trees.

Recoll — the feature ceiling

GPL-2.0-or-later C++ / Python Xapian Glass active · 1.44.1 · 2026-07

Homepage recoll.org. Recoll is the footwork (MIME, filters, query language, GUI); Xapian is the IR engine. That split matters: you can steal Recoll’s product ideas and must not steal the engine.

Formats

Native, no extra helper: plain text, HTML, maildir/mh/mbox, OpenDocument and OOXML via libxml2/libxslt, AbiWord, FB2, SVG, zip, classic Excel/PPT via Python stdlib. External helpers (subprocess): pdftotext (poppler, not xpdf), antiword / soffice / wvWare for .doc, unrtf, chmlib, mutagen, exiftool, libpff for PST, djvutxt, py7zr, unrar, ghostscript for PS. Nested containers to arbitrary depth — “DOCX attached to a message in a mailbox in a zip.” OCR and speech-to-text exist as optional Recoll config, default off because they are slow. Full list: features.html.

Queries

Xesam-descended language. Implicit AND; capital OR binds tighter; -term; "phrase"; "pride prejudice"o1 ordered proximity, "pride prejudice"p unordered; fields author: title: filename: ext: dir: mime: date: size>100k; wildcards * ?. Stemming at query time (capitalise a word to suppress). No body regex. Left-anchored regex exists in the term explorer / filename mode.

Index data structures

Xapian Glass (default in 1.4 and still the production backend): B-trees of 8 KB blocks, one file per table under ~/.recoll/xapiandb/.

TableFileContents
postlistpostlist.glassterm → chunked postings (docid + wdf); also value streams
termlisttermlist.glassdocid → terms in that document
positionposition.glass(term, docid) → positions, interpolative-coded
docdatadocdata.glassopaque blob. Recoll 1.24+ stores document text here for snippets
spelling / synonymlazy tablesaspell / synonyms

Posting format, from glass_postlist.cc: lists split into ~2 KB chunks. First-chunk key = length-prefixed term; later chunks keyed by term + first docid of the chunk (so skip is a B-tree seek). A chunk is: last-chunk flag, last−first docid, first wdf, then repeated (docid increment, wdf) packed with Xapian’s continuation-bit integers. Not PFor, roaring, or Elias-Fano. Positions use Moffat–Stuiver interpolative coding. Recoll stopped reconstructing snippets from positions because newer Xapian formats made that “unacceptably slow”; it stores UTF-8 text instead (+10–20% index size).

Stemming is not applied at index time. Surface forms go in; a stem dictionary is built after indexing and used to expand queries.

Manual rule of thumb: index size is the same order of magnitude as uncompressed extracted text. Images barely count. Incremental: mtime/size, optional MD5 for dup collapsing. Real-time: recollindex -m via inotify. Periodic cron is the common setup. Multithreaded extraction; Xapian writes are single-threaded. A 2016 PDF bench peaked around 1.2 GB RSS. Recoll can throttle via cgroups (documented); default nice/ionice is not a first-class story.

Steal: query-time stemming; nested ipath containers; stored text for snippets; filter ABI as external processes; dir: / date / size sugar. Beat: license; index fatness on text; no body regex; inotify daemon cost; single-threaded writer.

GNOME LocalSearch / TinySPARQL

GPL miners · LGPL library SQLite FTS5 renamed 2024

Tracker SPARQL is now TinySPARQL; Tracker Miners is LocalSearch. This is what GNOME Files searches. Not a product UI.

Formats: extract-modules for PDF (poppler-glib), OOXML, ODF, EPUB, HTML, AbiWord, PS, XPS, ISO, images, audio/video via FFmpeg/libav (GStreamer dropped in GNOME 48). Text extractor is only text/plain and text/markdown unless a more specific rule fires. No mail, no archive members, no CHM. PDF extractor is killed after ~5–10 s — large papers go missing.

Queries: SPARQL + fts:match, which is SQLite FTS5 (AND/OR/NOT, phrase, prefix *, NEAR). End users never see this. No Recoll-style dir: sugar. Regex is SPARQL FILTER(REGEX), not the FTS path.

Index: ontology classes → SQL tables; FTS properties gathered into a contentless FTS5 table so tokens live once. FTS5 postings are varint doclists inside SQLite B-trees (segments + automerge), with positions for phrase. Graphs (tracker:FileSystem, tracker:Documents, …) are separate attached DBs. No first-party size-vs-corpus number found.

Live / sandbox: always-on user systemd units, GIO/inotify. Extractor is a separate process with seccomp default-deny and Landlock (tightened after CVE-2023-43641). This jail is the one to copy. Recoll does not have it.

Steal: contentless FTS5 pattern; extractor jail; filename vs content graphs. Beat: body coverage, archives, mail, regex, standalone UI, SPARQL as the only language.

KDE Baloo

LGPL (KDE) LMDB, 12 named DBs KFileMetaData extractors

Plasma’s indexer. The wiki page that still says “sqlite and xapian” is outdated. Current Baloo is one LMDB environment at ~/.local/share/baloo/index, MDB_NOSUBDIR, historically a 256 GB mapsize.

DBIRole
postingdbterm → encoded list of docIds
positiondbterm → concatenated [docId : n : positions…]
docterms / docfilenametermsforward index, filename terms split out
idtree / idfilenamedirectory tree, names
documenttimedb / mtimedbmtime both ways
documentdatadb, indexingleveldb, failediddbmetadata, basic vs content, failures

DocID is 64-bit (fs id + inode). PostingCodec is custom; a 2018 rewrite to MDB_DUPSORT was prototyped and not landed. Integer coding (delta/varint/PFor) is unverified. PositionDB dominates space: T9805, ~11k text-ish docs, 554 MB file, PositionDB 51%, PostingDB 32%. Prefix-only word match: tutorial hits my_great_tutorial.txt, utorial does not. No regex. Text files over 10 MB skipped. ODF ZIP content is not indexed (wiki limitation). Classic Office goes through catdoc / xls2csv / catppt.

Always-on baloo_file + extractor helper, inotify. LMDB single-writer + deleted lock files have caused real corruption (bug 389848). Small RSS is a design goal; on-disk is not small if positions are on.

Steal: split filename vs content term spaces; stable file ids so rename is cheap; balooctl indexSize introspection; LMDB as a forward map (path↔id), not as the posting codec. Beat: ODF hole, 10 MB cap, prefix-only tokens, corruption story, no regex, no nested archives.

FSearch and ANGRYsearch — names only

FSearch (cboxdoerfer/fsearch, GPL-2, C/GTK3, 4.3k stars) is Everything for Linux and does not pretend otherwise. In-memory DynamicArray of files and folders: name offset, size, mtime, parent index. Several arrays kept sorted by different keys so sort is pointer swaps. Persist ~/.local/share/fsearch/fsearch.db — custom dump, not an IR index. Third-party: 2.3M entries → 104 MB disk. Query: AND/OR/NOT, * ?, PCRE2, modifiers file: folder: case: dm: size. Since 0.3: fanotify preferred, inotify fallback. No content.

ANGRYsearch (GPL-2, Python/Qt, last release 2022) stores paths in SQLite with FTS4/5. Fast mode cannot substring (Pirate not rate); slow mode is LIKE; F8 is regex on names. Author: ~1M files → ~200 MB, ~2 min. Cron recrawl, no inotify. Object lesson: FTS on paths is enough for filename UX; FSearch is the better clone.

At your scale (<5M files) the entire name table fits in RAM. That is the Everything lesson, and FSearch already proved it on Linux.

DocFetcher

EPL Java / SWT / Lucene FOSS frozen; Pro 2025

Portable Lucene index per chosen folder. Boolean / phrase / fuzzy term~ / proximity "a b"~3. Formats: PDF, Office, ODT, RTF, EPUB, HTML, Outlook in Pro. Claimed ~200 files/min — slow next to Recoll’s PDF numbers. Optional folder watcher applies on next GUI start. Closest license-shaped cousin (EPL/Apache, not GPL), wrong runtime. If you wanted a library, Tantivy is the Lucene analogue in Rust; you do not want a library.

plocate — the only modern filename posting codec on Linux

GNU locate: sorted names, front-compression, sequential scan. mlocate: per-directory mtime so updatedb skips unchanged dirs; still a name list. plocate (Steinar Gunderson, default on Debian/Fedora) is a trigram inverted index over filenames:

  • ZSTD dictionary trained on sampled names; filename blocks of ~32 names.
  • Robin Hood hash table of trigrams.
  • TurboPFor-encoded docid lists per trigram.
  • Query “foo” → trigrams → intersect → decompress candidate name blocks → match. Short needles and regex fall back to a scan. io_uring.

Daily updatedb, not live. GPL. Reimplement the idea (trigrams + PFor + compressed name store). Do not link it. This is the filename half of Cox’s paper, already in production on every Debian box.

rga and Clapgrep — refuse to index

rga (ripgrep-all, AGPL-3, Rust, v0.10.10 Nov 2025): ripgrep plus adapters — pandoc (epub/odt/docx/html), pdftotext, ffmpeg tags/subs, zip/tar/decompress, sqlite dump. Optional mail. Recurse archives depth 5. Cache of extracted text in SQLite+ZSTD since 0.10.6, max blob 2 MB. Still a linear search over (cached) text. Best “I will not maintain an index” tool. Do not vendor (AGPL); copy the adapter ABI.

Clapgrep (GPL-3, Rust/GTK4, v26.02): rga-class engine with a modern GNOME UI, PDF highlight, Nautilus extension, result cap. 2024–2026 newcomer. Still no inverted index; will not win on a 100 GB interactive corpus.

Pinot, Catfish, launchers, the dead

Pinot (GPL, Xapian + SQLite crawl history, gtkmm, 2005–2026): Recoll’s neglected cousin. inotify, nice 15, pause on battery. Format set is a subset. Steal the battery gate and crawl-history SQLite.

Catfish (Xfce): GUI over locate / find / optional Zeitgeist. Fulltext is readline substring. No index of its own.

Albert / Ulauncher / rofi: launchers. Filename or fd, not body search. Interoperate (KRunner / GNOME search provider), do not compete.

Beagle (2004–2009, C#/Lucene.Net): live inotify, 60+ formats, mail and IM as first-class. Died of Mono politics, not of Lucene. Strigi (KDE4, CLucene, SHA-1 dups, Xesam): replaced by Baloo. Tracker 1/2 was a global RDF store; Tracker 3 killed the central store; 2024 renamed. Glimpse (Manber & Wu 1993): block-addressed inverted file, index 2–30% of corpus, then agrep inside candidate blocks — the two-level idea Super Ferret still wants. mg / Managing Gigabytes: d-gap + Golomb/Elias, the textbook every posting codec is answering. Namazu / Hyper Estraier: Japanese morphology vs n-grams; Recoll’s CJK n-gram mode exists because segmenters are an extra dependency.

Windows — top three

1. Everything (voidtools) — steal the filename layer

Freeware, closed source. Does not walk the directory tree on NTFS. Reads the MFT sequentially, keeps names + parent FRNs in RAM, catches up from the USN Change Journal. Process can die; journal ID + next USN is the bookmark. FAT/network volumes are a slower folder-index path.

On-disk Everything.db is a BZIP cache of that MFT snapshot plus USN bookmarks, written on exit. Sorted folders/files with a small name codec (length 0 = same name as previous). Official RAM: ~35 MB for 250k files, ~100 MB for 1M. Build: ~5 s / ~1 min.

Query language is excellent on names: AND, |, !, phrase, wildcards, full regex, size: dm: ext: path:, hundreds of properties in 1.5.

1.5 content indexing is not an inverted index. Developer, 2021: extracted text is stored in RAM; designed for <1 GB of text; default types doc/docx/pdf/txt/xls/xlsx; IFilter for the rest. Do not copy this. si: can query Windows Search instead.

Linux mapping: there is no USN. Sequential metadata read per FS (ext4 inode table, btrfs tree, xfs AG btree) + fanotify/inotify with overflow → subtree rescan. Persist a compact name+parent snapshot so restart is seconds, not a walk.

2. Windows Search — steal the extractor isolation, not the store

Gatherer queues URLs; protocol handler in SearchProtocolHost.exe; IFilter + property handler in SearchFilterHost.exe (low integrity, ~100 MB cap, recycled). NTFS uses USN after the first crawl. Officially two indices: value indices for whole properties, inverted indices for words in text.

Vista–10: Windows.edb (ESE / JET Blue) plus, historically, CiFiles (*.ci / *.dir) for word postings. Win11: SQLite Windows.db + Windows-gather.db. Whether Win11 word postings still live as CiFiles is unverified in public forensics literature, which mostly parses the property store. Query: AQS (no regex) and Windows Search SQL CONTAINS/FREETEXT. Scope is not the whole disk unless Enhanced indexing is on. The property store balloons (Outlook on Win11 is a known inflator).

Steal: split value index vs inverted index; crashy parsers in a recycled worker; IFilter-style plugin ABI. Do not steal AQS, the gatherer URL queue, or “first N bytes of content in the property store.”

3. FileLocator Pro, with dtSearch as the dense-index cousin

FileLocator Pro (Mythicsoft, commercial) is the Windows regex-in-documents tool. Default is multi-threaded scan with IFilters / built-in Office converters. Optional cache of extracted text; optional user-built indexes since v8, not NRT. Agent Ransack is the same engine with indexing compiled out. Query: Boost regex, boolean, NEAR, phrase. This is what people pay for when Spotlight/AQS refuse regex.

dtSearch is the dense positional inverted index: official 1/8 to 1/3 of original documents, boolean/phrase/proximity/regex/fuzzy, scheduled updates, noise-word list, huge format list with built-in parsers. Closest commercial analogue of “Recoll, but they wrote the engine.” Not NRT. Leading wildcards are slow (prefix dictionary).

Honorable: Listary (MFT+USN, filename UX), Recoll-for-Windows, DocFetcher, Copernic, PowerToys Run (wraps Windows Search).

macOS — top three

1. Spotlight — steal the importer ABI

mds reads /dev/fsevents; mdworker runs a .mdimporter keyed by UTI; mds_stores writes /.Spotlight-V100/Store-V2/<UUID>/. Importers fill kMDItem* including kMDItemTextContent, which is searchable and not readable back via mdls (Apple privacy constraint). Super Ferret should be able to snippet.

On-disk (Oakley + Khatri, reverse-engineering): store.db / .store.db proprietary metadata (CNID + parent CNID); 0.indexHead, 0.indexIds, 0.indexPostings; journals / live files. Patents describe hot/cold term tables and delta merge — do not treat patents as the shipping format. Heavily used 500 GB volume: often 5–15 GB of Spotlight data (Oakley, not official).

Query: implicit AND, phrase, kind:; mdfind predicates with c/d/w modifiers. No regex. FSEvents can drop events; then mdutil -E. That unreliability is why EasyFind still exists. Mail moved to Core Spotlight; HoudahSpot lost Mail on Sonoma.

2. Alfred / Raycast — mostly not an index

Alfred uses Spotlight’s metadata index; a small local DB is ranking (usage), not content. Disable Spotlight and Alfred cannot find files. Raycast builds its own filename index of $HOME (respects .gitignore / .rayignore) and uses Spotlight/Windows Search for content. Steal ignore-file semantics. Do not wrap the OS content index.

3. FoxTrot Professional Search — own content index, scheduled

Commercial (CTM). Independent of Spotlight’s store. Reuses Spotlight importers for text and Quick Look for preview (importers feed only the first 10 MB unless overridden). Boolean, phrase, metadata, regex (Pro), facets. Update on demand or timer, not FSEvents-NRT. On-disk format unpublished. Sharp design: OS extractor ABI, your postings. Linux version: Recoll-style filters, your index.

HoudahSpot is the best query UI on Spotlight and will never find what Spotlight missed. EasyFind / Find Any File walk the filesystem, no index. DEVONthink is a document manager with its own index inside its databases, not a disk search.

Code search, because regex is a hard requirement

Word inverted indexes cannot answer /foo.*bar/ or handleRequest or [0-9a-f]{12}. Families:

FamilyStoresSize vs corpusUpdate
Trigram presence (Cox / csearch / Hound)each 3-gram → file ids; recheck with RE2~0.2× (Linux 3.1: 420 MB → 77 MB)merge postings
Positional trigrams (Zoekt)3-gram → offsets; content in shard~3.5×shard rebuild
Suffix array (livegrep)SA over concatenated corpus~3–5× RAMessentially static
Sparse n-grams (GitHub Blackbird)variable grams at high-weight boundaries~1× unique + index at GitHub scalesharded, closed
ripgrep / ugrepnothing, or ugrep’s per-dir sidecar0N/A

Cox’s algorithm (extract obligatory trigrams from the regexp, AND/OR posting lists, always recheck) is the only one that stays small and still prunes. Zoekt’s 3.5× is the wrong density trade. Suffix arrays are the wrong update model. Blackbird’s sparse grams are SOTA at 15 billion documents; at 5 million Cox + a dense posting codec is enough. Patterns with no 3-character literal become ANY → scan. Pair with a per-chunk Bloom (qgrep) so ANY is not “read 200 GB.”

If Super Ferret’s regex path is not faster than warm rg on typical code queries, the index is overhead. Unindexed files (too new, binary, generated) should fall back to mmap-grep, which is how Sourcegraph splits Zoekt vs searcher daemons.

Steal vs beat

Steal (license-clean ideas)

  1. plocate / Cox: trigrams → PFor postings → compressed names or files, then verify.
  2. Everything: parent-offset records, journal bookmark, rebuild-is-cheap, names in RAM at 5M files.
  3. FTS5 detail= and external content: the index is not the corpus.
  4. Recoll: query-time stemming, stored extracted text for snippets, nested containers, Xesam-ish query surface.
  5. LocalSearch: seccomp+Landlock extractor; contentless FTS so text is stored once.
  6. Spotlight / IFilter: plugin ABI keyed by type; recycled, resource-capped worker.
  7. Pinot / Recoll AC script: battery, idle, ionice. Your stated product requirement; almost nobody does it well.
  8. FSearch query sugar on the name half: file: dm: size ranges, type-as-you-go.
  9. FileLocator / dtSearch: regex as a first-class operator, not an afterthought.
  10. Strigi/Recoll: content-hash dup detection. Cheap, loved on node_modules.
  11. Raycast: .gitignore as index exclude.
  12. VictoriaLogs: do not invert high-frequency body tokens; group similar files; bloom then scan compressed columns. See indexing options.
