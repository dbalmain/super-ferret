Super Ferret · competitive + architecture brief

Desktop search, surveyed for a from-scratch build

Linux is the product. macOS and Windows are the bars to beat on filename speed and extractor plugins. The index is yours to write — denser than Recoll, more capable than FSearch, not a port of old Ferret.

Verdict in one screen

Nothing on Linux is Everything-fast on names and Recoll-deep on documents and rga-honest on regex, in one process, with a small index. That combination is the product.

Windows and macOS, compressed

Windows: Everything for names (MFT + USN, ~100 bytes/file in RAM). Windows Search for OS content (IFilter + inverted index in ESE, SQLite on Win11). FileLocator Pro / dtSearch for regex-over-documents. Everything 1.5 “content index” is extracted text in RAM with a 1 GB-of-text cap — do not copy that.

macOS: Spotlight is the OS (FSEvents + .mdimporter + proprietary store with postings). Alfred wraps it. Raycast builds its own filename index and still uses Spotlight for content. FoxTrot is the only mainstream Mac app with its own content index and regex; it reuses Spotlight importers and is scheduled, not NRT.

The hole

Four lineages grew up on Linux and never merged:

  1. IR desktop search — Recoll, Pinot, DocFetcher. Inverted index, extractors, boolean/phrase. Slow to start, fat on text, GPL or Java.
  2. DE metadata miners — LocalSearch, Baloo. Always on, small RSS, weak body quality, no regex, integration instead of a product UI.
  3. Everything clones — FSearch, ANGRYsearch. Instant names, no body.
  4. Scan-at-query — Catfish, rga, Clapgrep. Honest regex, no index to maintain.

Glimpse (1993) already knew the missing move: a cheap first stage (block ids / trigrams) plus verification. plocate is that idea applied to filenames with TurboPFor. Super Ferret is that idea applied to a personal corpus that also contains PDFs and code.

Implied stack

Not a spec — a picture of what the two reports jointly recommend, pending the density question.

watcher (fanotify/inotify, overflow → subtree walk) → coalesce queue (debounce path, nice/ionice, idle/AC gates) → jailed extractors (seccomp+Landlock; spawn pdftotext, never link poppler) → four stores: RAM names + parent ids (Everything / FSearch) columnar metadata (mtime, size, ext — VL-style dict/int) body: bloom+scan and/or PEF (the open question) Cox trigrams for regex (≈0.2× corpus, then recheck) → snippets from stored extracted text for PDF/Office; re-read files for code → later: mail/OCR as extra fields; HNSW sidecar for images; ASR field for audio

Do not link Xapian, Tantivy, Lucene, or poppler. Do spawn GPL helpers. Do reimplement PEF / SIMD-BP128 / Cox / roaring — those are algorithms, not products. Old Ferret’s segment + skip-interval mental model is still the right write model; every encoding in it should be replaced.

How to read

  • Landscape is “what exists, what it indexes, what the files on disk actually are.” Read it to know who you are competing with and which extractor/query ideas to steal.
  • Indexing options is “what you could build.” Encodings have measured bits/int. VictoriaLogs is unpacked because you named it. The recommended composition is at the end.
  • Claims that are reverse-engineered or vendor-only are marked. Primary sources are linked from each report.
